# 智能推薦系統

除了 AI 酒保的對話式推薦，系統還提供基於演算法的智能推薦功能，透過分析用戶的飲用記錄和偏好，主動推薦可能喜歡的調酒。

## 推薦系統架構

推薦系統採用**混合式推薦策略**，結合多種演算法來達到最佳效果：

1. **協同過濾**：基於相似用戶的喜好
2. **內容過濾**：基於調酒的屬性和標籤
3. **探索與利用平衡**：在熟悉和新奇之間取得平衡

## 兩種推薦模式

### 模式 1：平衡模式（Balanced Mode）

平衡模式適合大多數用戶，在安全與冒險之間取得最佳平衡。

#### 推薦組成（以 20 杯為例）

- **40% 安全優先**（8 杯）：高相似度推薦
  - 目標：讓用戶感到舒適和滿意
  - 策略：推薦與用戶喜愛調酒相似度高的選擇
  - 相似度分數：> 15 分

- **30% 冒險探索**（6 杯）：中等相似度 + 新類型
  - 目標：擴展用戶的口味範圍
  - 策略：推薦有一定相似性但包含新元素的調酒
  - 相似度分數：10-15 分
  - 特別關注：用戶未嘗試過的基酒類型

- **15% 隱藏寶石**（3 杯）：高品質小眾調酒
  - 目標：讓用戶發現專業推薦但不太知名的好酒
  - 策略：專業評分 ≥ 4.5 且公眾評論 ≤ 20
  - 推薦理由範例：「專業評分 4.7★ 的隱藏珍品」

- **15% 熱門推薦**（3 杯）：大眾喜愛調酒
  - 目標：提供社交話題和共同體驗
  - 策略：公眾評論數 ≥ 50
  - 推薦理由範例：「150 人都給了好評！」

#### 適合對象

- 想要穩定體驗的用戶
- 希望逐步探索新口味
- 追求品質與驚喜兼顧

### 模式 2：冒險模式（Adventurous Mode）

冒險模式適合喜歡嘗試新事物、追求刺激和變化的用戶。

#### 推薦組成（以 20 杯為例）

- **20% 安全優先**（4 杯）：高相似度推薦
  - 保留少量熟悉選項作為安全網
  - 確保不會完全偏離用戶喜好

- **60% 冒險探索**（12 杯）：大量新奇組合
  - 目標：最大化新體驗和驚喜
  - 策略：
    - 推薦用戶從未嘗試的基酒
    - 推薦跨風格、跨分類的調酒
    - 推薦風味對比強烈的選擇
  - 相似度分數：5-15 分
  - 特別關注：完全陌生的基酒和風味組合

- **15% 隱藏寶石**（3 杯）：高品質小眾調酒
  - 與平衡模式相同
  - 專業推薦的優質選擇

- **5% 熱門推薦**（1 杯）：大眾喜愛調酒
  - 比例降低，因為冒險型用戶較不追隨主流
  - 僅保留極少量作為參考

#### 適合對象

- 喜歡嘗試新事物的用戶
- 追求驚喜和變化
- 想要快速擴展調酒知識

## 相似度計算機制

系統使用多維度評分來計算調酒與用戶偏好的相似度：

### 評分公式（總分最高 40 分）

#### 1. 標籤匹配分數（最高 20 分）

- **基酒匹配**：每個匹配的基酒 +4 分
  - 從用戶最愛的前 3 種基酒中匹配
  - 範例：用戶喜歡琴酒，推薦琴酒調酒 +4 分

- **風味匹配**：每個匹配的風味 +2 分
  - 從用戶最愛的前 5 種風味中匹配
  - 範例：用戶喜歡柑橘味，推薦含柑橘的調酒 +2 分

- **風格匹配**：每個匹配的風格 +1 分
  - 從用戶最愛的前 5 種風格中匹配
  - 範例：用戶喜歡經典款，推薦經典調酒 +1 分

#### 2. 口味接近度（最高 10 分）

計算公式：
```
口味分數 = 10 - (酒精強度差距 + 甜度差距) / 2
```

- **酒精強度**（0-10）：與用戶平均偏好的差距
- **甜度**（0-10）：與用戶平均偏好的差距
- **權重調整**：× 0.8

範例：
- 用戶平均喜好：強度 7、甜度 3
- 候選調酒：強度 8、甜度 4
- 差距：|7-8| + |3-4| = 2
- 分數：(10 - 2/2) × 0.8 = 7.2 分

#### 3. 品質分數（最高 10 分）

計算公式：
```
品質分數 = 專業評分 × 2 × 0.6
```

- 使用 Difford's Guide 的專業評分（0-5 星）
- 放大 2 倍後再調整權重
- 範例：4.5 星調酒 = 4.5 × 2 × 0.6 = 5.4 分

#### 4. 流行度調整（最高 3 分）

- **熱門調酒**（公眾評論 ≥ 50）：+3 × 0.3 = 0.9 分
- **隱藏寶石**（專業評分 ≥ 4.5 且評論 ≤ 20）：+2 × 0.3 = 0.6 分

#### 5. 隨機微調

- 加入 0-0.1 的隨機值
- 目的：避免完全相同分數導致的排序固化
- 確保每次推薦都有微妙變化

### 相似度分數解讀

- **20+ 分**：非常符合用戶口味，幾乎確定會喜歡
- **15-20 分**：高度相似，大機率喜歡（安全區）
- **10-15 分**：中等相似，值得嘗試（冒險區）
- **5-10 分**：低相似度，需要勇氣嘗試
- **0-5 分**：完全陌生，極度冒險

## 推薦多樣性保證

為了避免推薦結果過於單一，系統實施多項多樣化策略：

### 1. 分散化抽取

從每個推薦池中抽取時，優先選擇不同基酒和風味的調酒：

**第一輪**：選擇不同基酒
- 確保推薦清單涵蓋多種基酒
- 避免 20 杯都是琴酒

**第二輪**：選擇不同風味
- 在相同基酒內選擇不同風味組合
- 例如：琴酒 + 柑橘、琴酒 + 草本

**第三輪**：均勻間隔抽取
- 從剩餘調酒中均勻抽取
- 避免集中在特定區間

### 2. 智能打亂順序

推薦清單不按分數排序，而是智能打亂：

- **避免連續相同基酒**：連續兩杯不會有相同基酒
- **混合推薦類型**：安全、冒險、寶石、熱門穿插出現
- **製造驚喜感**：讓用戶在瀏覽時保持新鮮感

### 3. 去重與排除

- **已喝過的調酒**：自動排除
- **已推薦過的調酒**：支援分頁時排除（避免重複）
- **同一調酒只出現一次**：確保推薦清單無重複

## 用戶偏好分析

推薦系統的基礎是準確的用戶偏好分析：

### 分析維度

#### 1. 喜愛標籤（基於 liked/loved 調酒）

統計用戶喜歡的調酒中出現最多的：
- **基酒類型**（Top 3）：琴酒、伏特加、蘭姆酒...
- **風味標籤**（Top 5）：柑橘、草本、莓果、熱帶...
- **風格標籤**（Top 5）：經典、清爽、濃郁、創意...

#### 2. 口味範圍（基於 liked/loved 調酒）

統計偏好範圍：
- **酒精強度**：最小值、最大值、平均值
- **甜度**：最小值、最大值、平均值

範例：
```json
{
  "strength": { "min": 5, "max": 9, "avg": 7 },
  "sweetness": { "min": 2, "max": 6, "avg": 4 }
}
```

#### 3. 行為模式（基於所有紀錄）

分析用戶的飲用習慣：
- **時段分佈**：早晨、下午、晚上、深夜
- **場合分佈**：慶祝、放鬆、約會、聚會...
- **地點分佈**：家中、酒吧、餐廳...

### 冷啟動處理

對於新用戶（沒有飲用記錄），系統提供：

- **經典入門推薦**：評分 ≥ 4.0、難度簡單/中等
- **隨機抽樣**：確保推薦的多樣性
- **推薦理由**：「經典入門推薦」

## 推薦理由生成

每個推薦都附帶個人化的推薦理由，幫助用戶理解為什麼推薦這杯酒：

### 理由範例

**安全優先**：
- 「符合你對琴酒的偏好」
- 「與你喜歡的調酒很相似」

**冒險探索**：
- 「嘗試新的蘭姆酒基底？」
- 「探索新的風味組合」

**隱藏寶石**：
- 「專業評分 4.7★ 的隱藏珍品」
- 「內行人才知道的優質選擇」

**熱門推薦**：
- 「150 人都給了好評！」
- 「最受歡迎的經典之一」

## 推薦流程

1. **取得用戶偏好**：分析飲用記錄，提取偏好特徵
2. **候選調酒抽樣**：從資料庫隨機抽樣 1000-2000 杯（避免字母偏差）
3. **計算相似度**：為每杯候選調酒計算相似度分數
4. **分類到推薦池**：根據分數和屬性分配到四個池
5. **按比例抽取**：根據模式（平衡/冒險）從各池抽取
6. **多樣化處理**：確保基酒、風味的多樣性
7. **智能排序**：打亂順序，避免連續相同基酒
8. **附加推薦理由**：為每杯調酒生成個人化說明

## 使用場景

### 場景 1：首頁探索

用戶登入後，首頁顯示：
- **今日推薦**：根據當前模式生成的 20 杯推薦
- **一鍵切換模式**：快速切換平衡/冒險模式
- **無限瀏覽**：下滑載入更多（排除已顯示的）

### 場景 2：口味探索

用戶想要系統性地探索新口味：
1. 使用平衡模式建立基礎偏好
2. 記錄 10-20 杯的飲用體驗
3. 切換到冒險模式快速擴展
4. 發現新的喜愛類型

### 場景 3：派對準備

用戶要為派對選酒：
- 切換到平衡模式
- 查看「熱門推薦」類型
- 選擇大眾接受度高的調酒

## 與 AI 酒保的整合

推薦系統與 AI 酒保相輔相成：

### AI 酒保優勢
- 理解複雜的自然語言需求
- 提供互動式的對話體驗
- 可以追問和細化需求

### 推薦系統優勢
- 主動推薦，無需輸入

### 整合場景

**從推薦到對話**：
```
用戶在推薦頁看到調酒 → 點擊「問 AI」→ AI 酒保介紹這杯酒
```

**從對話到推薦**：
```
用戶與 AI 聊天 → AI 了解偏好 → 系統更新推薦演算法 → 推薦頁即時更新
```

## 效能優化

### 1. 隨機抽樣策略
- 每次從資料庫隨機抽樣 1000-2000 杯
- 避免遍歷所有調酒（8000+ 杯）
- 犧牲少量準確性換取速度

### 2. 記憶化（Caching）
- 用戶偏好分析結果快取
- 相似度計算結果快取（5 分鐘）
- 減少重複計算

### 3. 分頁載入
- 支援 `exclude_ids` 參數
- 前端可以無限下滑載入
- 每次載入 20 杯新推薦
