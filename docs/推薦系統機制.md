# 調酒推薦系統機制

## 系統概述

本系統提供兩種互補的推薦機制，結合 AI 智能推薦與計算型推薦，為用戶提供全面的調酒探索體驗。兩種模式各有特色，可獨立運作也可協同工作。

---

## 模式一：AI 動態推薦（智能對話模式）

### 核心特色

此模式由 **LangGraph Agent** 驅動，透過自然語言對話即時理解用戶需求，提供高度情境化的智能推薦。這是系統的主要互動方式。

### 運作機制

#### 1. 對話式需求理解

AI 酒保會分析用戶的每一句話，理解其真實需求：

**理解維度**：
- **口味偏好**：「清爽」、「濃郁」、「酸甜」、「苦味」
- **情境需求**：「約會」、「派對」、「獨飲」、「夏日海邊」
- **材料限制**：「有琴酒」、「不要奎寧水」、「想用龍舌蘭」
- **屬性要求**：「低卡路里」、「簡單」、「高顏值」、「低酒精」

#### 2. 智能工具選擇

AI 會根據理解到的需求，自動選擇最適合的搜尋策略：

**工具選擇範例**：

| 用戶描述 | AI 選擇的工具 | 理由 |
|---------|-------------|------|
| 「酸酸甜甜的」 | 語義口味搜尋 | 抽象口味描述，需要語義理解 |
| 「適合約會的」 | 語義情境搜尋 | 情境描述，需匹配氛圍 |
| 「有琴酒的」 | 材料搜尋 | 明確材料指定 |
| 「卡路里低於 200」 | 屬性篩選 | 具體數值條件 |
| 「Mojito 怎麼做」 | 名稱搜尋 | 特定調酒查詢 |
| 「隨便推薦一個」 | 隨機推薦 | 探索意願 |

#### 3. 多輪對話優化

系統會記憶對話脈絡，持續優化推薦：

**對話範例（探索模式）**：
```
第 1 輪
用戶：想喝清爽的
AI：（語義搜尋：清爽）→ 推薦 Mojito
狀態：current_query = {口味: "清爽"}

第 2 輪  
用戶：換一個
AI：（排除 Mojito，繼續搜尋清爽）→ 推薦 Gin Tonic
狀態：recommended_cocktails = ["Mojito"]

第 3 輪
用戶：要低酒精的
AI：（累積條件：清爽 + 低酒精）→ 推薦 Aperol Spritz
狀態：current_query = {口味: "清爽", 酒精: "低"}
```

#### 4. 上下文記憶機制

**記憶內容**：
- **累積查詢條件** (`current_query`)：持續累積用戶提到的所有篩選條件
- **已推薦清單** (`recommended_cocktails`)：避免重複推薦相同調酒
- **最後推薦** (`last_recommendation`)：方便追問詳情或替換
- **對話歷史** (`messages`)：完整對話記錄，理解上下文

### 推薦策略

#### 語義搜尋策略（RAG 技術）

**技術原理**：
1. 將用戶描述轉換為向量
2. 在 Qdrant 向量資料庫中搜尋相似調酒
3. 返回語義最相關的結果

**優勢**：
- 理解抽象概念：「清爽」、「濃郁」、「複雜」
- 跨越語言障礙：中英文都能理解
- 捕捉情境氛圍：「浪漫」、「派對」、「慵懶」
- 語義關聯：能找到概念相似但描述不同的調酒

**搜尋維度**：
- **口味向量**：基於調酒的口味描述和風味特徵
- **情境向量**：基於適合的場合、氛圍和使用情境
- **混合搜尋**：結合多種向量進行綜合評分

#### 屬性篩選策略

當用戶提供具體條件時使用：

**可篩選屬性**：
- **酒精強度**：無酒精、低（< 15%）、中（15-25%）、高（> 25%）
- **甜度**：不甜、微甜、甜
- **卡路里**：範圍篩選（如 < 200 大卡）
- **難度**：簡單、中等、困難
- **評分**：最低評分要求（如 ≥ 4.0 分）
- **類別**：Martini、Sour、Tiki 等

**適用情境**：
- 健康考量：低卡路里、低酒精
- 技能限制：僅推薦簡單調酒
- 品質要求：高評分調酒
- 明確偏好：特定類別或風格

### 適用情境

- **探索需求**：用戶想嘗試新口味，需求較為模糊
- **情境推薦**：根據場合、心情、季節尋找合適調酒
- **互動體驗**：享受與 AI 對話的過程
- **學習需求**：想了解調酒知識和製作方法

## 模式二：計算型推薦（冒險與精準模式）

### 核心特色

此模式基於**計算演算法**，不依賴 LLM，而是透過數學計算和用戶偏好匹配來推薦調酒。分為兩種子模式：**冒險模式**和**精準模式**。

### 子模式一：冒險模式（Adventure Mode）

#### 設計理念

幫助用戶跳出舒適圈，探索意想不到的調酒。推薦邏輯會**降低**用戶已知偏好的權重，增加隨機性和新穎性。

#### 運作機制

1. **反向偏好匹配**：
   - 識別用戶常喝的基酒、口味、類別
   - **降低**這些熟悉元素的推薦權重
   - **提高**用戶較少接觸的類型權重

2. **新穎度計算**：
   - 計算調酒與用戶歷史選擇的差異度
   - 差異度越大，推薦分數越高
   - 確保推薦結果具有驚喜感

3. **隨機性注入**：
   - 在候選調酒中加入隨機因子
   - 不完全依賴計算分數
   - 增加推薦的不可預測性

4. **品質門檻**：
   - 雖然強調新穎，但仍需符合基本品質標準
   - 評分過低（如 < 3.0）的調酒不會被推薦
   - 確保冒險不等於踩雷

#### 推薦邏輯

**分數計算公式**：
```
冒險分數 = (新穎度 × 0.5) + (隨機值 × 0.3) + (品質分數 × 0.2)

其中：
- 新穎度：與用戶偏好的差異程度（0-1）
- 隨機值：隨機生成的值（0-1）
- 品質分數：調酒評分 / 5（正規化到 0-1）
```

#### 適用情境

- **想嘗試新口味**：厭倦了常喝的調酒
- **擴展品味範圍**：想探索不同的調酒類型
- **尋求驚喜**：享受未知的探索樂趣
- **派對場合**：需要多樣化的選擇

#### 範例情境

**用戶背景**：
- 常喝：Gin & Tonic、Martini（琴酒類）
- 偏好：清爽、不甜
- 避免：濃烈、複雜

**冒險模式推薦**：
- 推薦 Jungle Bird（蘭姆酒基底、熱帶風味）
- 推薦 Whiskey Sour（威士忌基底、酸甜平衡）
- 推薦 Pisco Sour（皮斯可基底、獨特口感）

→ **邏輯**：跳出琴酒舒適圈，嘗試不同基酒和風味

### 子模式二：精準模式（Precision Mode）

#### 設計理念

基於用戶明確的偏好設定和歷史行為，推薦最符合用戶口味的調酒。強調**個人化**和**相關性**。

#### 運作機制

1. **偏好分析**：
   - 分析用戶設定的喜好（基酒、口味、甜度等）
   - 分析用戶的收藏清單
   - 分析用戶的飲用記錄

2. **權重計算**：
   - 為每個偏好維度賦予權重
   - 明確設定的偏好權重較高
   - 行為暗示的偏好權重較低

3. **匹配評分**：
   - 計算候選調酒與用戶偏好的匹配度
   - 匹配度越高，推薦分數越高
   - 完全符合偏好的調酒優先推薦

4. **排除過濾**：
   - 嚴格排除用戶不喜歡的材料
   - 排除已收藏或已喝過的調酒（可選）
   - 確保推薦結果符合用戶期待

#### 推薦邏輯

**分數計算公式**：
```
精準分數 = Σ(偏好匹配度 × 權重) - 排除項懲罰

其中：
- 基酒匹配（權重 0.3）
- 口味匹配（權重 0.25）
- 甜度匹配（權重 0.15）
- 酒精強度匹配（權重 0.15）
- 難度匹配（權重 0.1）
- 評分加成（權重 0.05）
```

#### 偏好來源

1. **明確偏好設定** (`preferences` collection)：
   - 用戶在設定頁面選擇的偏好
   - 包括喜歡的基酒、口味、甜度等
   - 可設定排除的材料

2. **收藏調酒** (`favorites` collection)：
   - 分析用戶收藏的調酒特徵
   - 提取共同點作為隱性偏好
   - 推薦類似風格的調酒

3. **飲用記錄** (`drinking_records` collection)：
   - 記錄用戶飲用過的調酒
   - 分析飲用頻率和時間
   - 推薦用戶可能喜歡但未嘗試的調酒

#### 適用情境

- **明確偏好**：用戶清楚知道自己喜歡什麼
- **高效選擇**：不想花時間探索，想快速找到喜歡的
- **特殊限制**：有健康、宗教或個人限制
- **追求品質**：想要最符合口味的高分調酒

#### 範例情境

**用戶設定**：
- 喜歡基酒：琴酒、伏特加
- 偏好口味：清爽、草本
- 甜度：不甜
- 酒精強度：中等
- 排除材料：奎寧水

**精準模式推薦**：
- 推薦 Martini（琴酒、不甜、清爽）
- 推薦 Gibson（琴酒、類似 Martini）
- 推薦 Aviation（琴酒、花香、優雅）

→ **邏輯**：完全符合用戶偏好設定

## 兩種模式的協作

### 互補性

- **AI 動態推薦**：靈活、互動、適合探索
- **冒險模式**：挑戰、新穎、適合擴展品味
- **精準模式**：高效、準確、適合快速選擇

### 使用時機建議

| 情境 | 推薦模式 |
|------|---------|
| 不知道想喝什麼 | AI 動態推薦 |
| 想聊天互動 | AI 動態推薦 |
| 想嘗試新口味 | 冒險模式 |
| 想要驚喜 | 冒險模式 |
| 有明確偏好 | 精準模式 |
| 快速決策 | 精準模式 |
| 學習調酒知識 | AI 動態推薦 |
| 根據情境選擇 | AI 動態推薦 |

### 系統整合

三種模式在系統中的位置：

1. **AI 動態推薦**：
   - 位於對話介面
   - 主要互動方式
   - 需要 LLM API

2. **冒險模式**：
   - 位於調酒探索頁面
   - 「給我驚喜」按鈕
   - 純計算，無需 API

3. **精準模式**：
   - 位於個人推薦頁面
   - 「為你推薦」區塊
   - 純計算，無需 API

## 技術實現

### AI 動態推薦

**技術棧**：
- LangGraph Agent 狀態管理
- Qdrant 向量搜尋
- MongoDB 資料查詢
- LLM 自然語言處理

**API 端點**：`POST /api/chat/message`

### 計算型推薦

**技術棧**：
- Python 計算邏輯
- MongoDB 聚合查詢
- 偏好匹配演算法
- 無需 LLM

**API 端點**：
- 冒險模式：`GET /api/recommendations/adventure`
- 精準模式：`GET /api/recommendations/precision`

---

## 優勢總結

### AI 動態推薦優勢

- 自然語言理解，無需學習特定格式
- 語義搜尋，理解抽象概念
- 多輪對話，持續優化結果
- 個性化互動，提供情境化建議

### 冒險模式優勢

- 幫助用戶發現新口味
- 避免推薦同質化
- 增加探索樂趣
- 擴展用戶品味範圍

### 精準模式優勢

- 快速找到符合偏好的調酒
- 高度個人化
- 避免不喜歡的元素
- 提高選擇效率

### 綜合優勢

透過結合這三種模式，本系統能夠：
- 滿足不同場景的推薦需求
- 提供從探索到精準的完整體驗
- 兼顧互動性與效率
- 適應不同用戶的使用習慣
