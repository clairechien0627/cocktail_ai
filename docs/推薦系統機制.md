# 調酒推薦系統機制

## 系統概述

本系統提供兩種互補的推薦機制，結合 AI 智能推薦與計算型推薦，為用戶提供全面的調酒探索體驗。兩種模式各有特色，可獨立運作也可協同工作。

---

## 模式一：AI 動態推薦（智能對話模式）

### 核心特色

此模式由 **LangGraph Agent** 驅動，透過自然語言對話即時理解用戶需求，提供高度情境化的智能推薦。這是系統的主要互動方式。

### 運作機制

#### 1. 對話式需求理解

AI 酒保會分析用戶的每一句話，理解其真實需求：

**理解維度**：
- **口味偏好**：「清爽」、「濃郁」、「酸甜」、「苦味」
- **情境需求**：「約會」、「派對」、「獨飲」、「夏日海邊」
- **材料限制**：「有琴酒」、「不要奎寧水」、「想用龍舌蘭」
- **屬性要求**：「低卡路里」、「簡單」、「高顏值」、「低酒精」

#### 2. 智能工具選擇

AI 會根據理解到的需求，自動選擇最適合的搜尋策略：

**工具選擇範例**：

| 用戶描述 | AI 選擇的工具 | 理由 |
|---------|-------------|------|
| 「酸酸甜甜的」 | 語義口味搜尋 | 抽象口味描述，需要語義理解 |
| 「適合約會的」 | 語義情境搜尋 | 情境描述，需匹配氛圍 |
| 「有琴酒的」 | 材料搜尋 | 明確材料指定 |
| 「卡路里低於 200」 | 屬性篩選 | 具體數值條件 |
| 「Mojito 怎麼做」 | 名稱搜尋 | 特定調酒查詢 |
| 「隨便推薦一個」 | 隨機推薦 | 探索意願 |

#### 3. 多輪對話優化

系統會記憶對話脈絡，持續優化推薦：

**對話範例（探索模式）**：
```
第 1 輪
用戶：想喝清爽的
AI：（語義搜尋：清爽）→ 推薦 Mojito
狀態：current_query = {口味: "清爽"}

第 2 輪  
用戶：換一個
AI：（排除 Mojito，繼續搜尋清爽）→ 推薦 Gin Tonic
狀態：recommended_cocktails = ["Mojito"]

第 3 輪
用戶：要低酒精的
AI：（累積條件：清爽 + 低酒精）→ 推薦 Aperol Spritz
狀態：current_query = {口味: "清爽", 酒精: "低"}
```

#### 4. 上下文記憶機制

**記憶內容**：
- **累積查詢條件** (`current_query`)：持續累積用戶提到的所有篩選條件
- **已推薦清單** (`recommended_cocktails`)：避免重複推薦相同調酒
- **最後推薦** (`last_recommendation`)：方便追問詳情或替換
- **對話歷史** (`messages`)：完整對話記錄，理解上下文

### 推薦策略

#### 語義搜尋策略（RAG 技術）

**技術原理**：
1. 將用戶描述轉換為向量
2. 在 Qdrant 向量資料庫中搜尋相似調酒
3. 返回語義最相關的結果

**優勢**：
- 理解抽象概念：「清爽」、「濃郁」、「複雜」
- 跨越語言障礙：中英文都能理解
- 捕捉情境氛圍：「浪漫」、「派對」、「慵懶」
- 語義關聯：能找到概念相似但描述不同的調酒

**搜尋維度**：
- **口味向量**：基於調酒的口味描述和風味特徵
- **情境向量**：基於適合的場合、氛圍和使用情境
- **混合搜尋**：結合多種向量進行綜合評分

#### 屬性篩選策略

當用戶提供具體條件時使用：

**可篩選屬性**：
- **酒精強度**：無酒精、低（< 15%）、中（15-25%）、高（> 25%）
- **甜度**：不甜、微甜、甜
- **卡路里**：範圍篩選（如 < 200 大卡）
- **難度**：簡單、中等、困難
- **評分**：最低評分要求（如 ≥ 4.0 分）
- **類別**：Martini、Sour、Tiki 等

**適用情境**：
- 健康考量：低卡路里、低酒精
- 技能限制：僅推薦簡單調酒
- 品質要求：高評分調酒
- 明確偏好：特定類別或風格

### 適用情境

- **探索需求**：用戶想嘗試新口味，需求較為模糊
- **情境推薦**：根據場合、心情、季節尋找合適調酒
- **互動體驗**：享受與 AI 對話的過程
- **學習需求**：想了解調酒知識和製作方法

## 模式二：計算型推薦（智能混合引擎）

### 核心特色

此模式基於**計算演算法**，不依賴 LLM，而是透過數學計算和用戶偏好匹配來推薦調酒。系統提供兩種探索模式：**平衡模式（Balanced）**和**冒險模式（Adventurous）**，自動混合四種推薦策略。

### 四種推薦策略池

推薦系統將候選調酒分為四個互斥的池：

#### 1. 安全優先池（Safe Pool）
- **特徵**：相似度分數 > 15
- **邏輯**：高度符合用戶偏好（基酒、口味、甜度等）
- **推薦原因**：「符合你對琴酒的偏好」、「與你喜歡的調酒很相似」

#### 2. 冒險探索池（Adventure Pool）
- **特徵**：相似度分數 10-15，或包含用戶未嘗試過的基酒
- **邏輯**：中等相似度，幫助探索新類型
- **推薦原因**：「嘗試新的蘭姆酒基底？」、「探索新的風味組合」

#### 3. 隱藏寶石池（Hidden Gems）
- **特徵**：專業評分 ≥ 4.5 且公眾評論數 ≤ 20
- **邏輯**：高品質但較少人知道的調酒
- **推薦原因**：「專業評分 4.8★ 的隱藏珍品」

#### 4. 熱門推薦池（Popular Pool）
- **特徵**：公眾評論數 ≥ 50
- **邏輯**：大眾喜愛的熱門調酒
- **推薦原因**：「120 人都給了好評！」

### 探索模式

#### 平衡模式（Balanced Mode）- 預設

**比例分配**：
- 40% 安全優先（8/20）
- 30% 冒險探索（6/20）
- 15% 隱藏寶石（3/20）
- 15% 熱門推薦（3/20）

**適用情境**：
- 日常使用
- 想在熟悉中帶點新意
- 穩定探索

#### 冒險模式（Adventurous Mode）

**比例分配**：
- 20% 安全優先（4/20）
- 60% 冒險探索（12/20）
- 15% 隱藏寶石（3/20）
- 5% 熱門推薦（1/20）

**適用情境**：
- 想嘗試新口味
- 擴展品味範圍
- 尋求驚喜

### 運作機制

#### 1. 用戶偏好分析

系統首先分析用戶的飲用記錄，提取偏好：
- 喜愛的基酒類型（出現頻率）
- 偏好的風味標籤
- 常選擇的風格
- 酒精強度和甜度範圍

#### 2. 相似度計算

對每個候選調酒計算相似度分數：

**分數計算公式**：
```
相似度分數 = 基酒匹配分 + 口味匹配分 + 甜度匹配分 + 酒精強度匹配分

基酒匹配：每個匹配的基酒 +5 分
口味匹配：每個匹配的風味標籤 +3 分  
甜度匹配：甜度範圍相符 +2 分
酒精強度匹配：強度範圍相符 +2 分
```

#### 3. 智能分池

根據相似度分數和調酒屬性，自動分配到四個池：
- 分數 > 15 → 安全優先池
- 分數 10-15 或新基酒 → 冒險探索池
- 專業評分 ≥ 4.5 且評論數 ≤ 20 → 隱藏寶石池
- 評論數 ≥ 50 → 熱門推薦池

**互斥性**：每個調酒只能在一個池中（按優先級：隱藏寶石 > 熱門 > 安全/冒險）

#### 4. 分散化抽取

為確保推薦多樣性，使用三輪抽取策略：

**第一輪**：優先選擇不同基酒的調酒  
**第二輪**：優先選擇不同風味的調酒  
**第三輪**：從剩餘中均勻間隔抽取

#### 5. 智能排序

打亂推薦順序，避免相同基酒連續出現：
- 檢查相鄰調酒的基酒
- 若有重複，調整順序
- 確保多樣化的體驗

#### 6. 冷啟動處理

對於新用戶（無飲用記錄）：
- 推薦經典、簡單、高評分調酒
- 專業評分 ≥ 4.0
- 難度：簡單或中等
- 使用隨機抽樣確保多樣性

### 技術特色

#### 動態隨機抽樣
- 每次從 1000-2000 個隨機候選中計算
- 解決字母順序偏差問題
- 確保每次推薦結果不同

#### 去重機制
- 排除已飲用的調酒
- 支援排除已推薦的調酒（分頁功能）
- 確保推薦列表無重複

#### 個性化推薦理由
- 每個調酒附帶推薦原因
- 說明為何推薦此調酒
- 標記推薦類型（safe/adventure/hidden_gem/popular）

## 兩種模式的協作

### 互補性

- **AI 動態推薦**：靈活、互動、適合探索和對話
- **計算型推薦**：高效、多樣、自動混合四種策略

### 使用時機建議

| 情境 | 推薦模式 |
|------|---------|
| 不知道想喝什麼 | AI 動態推薦 |
| 想聊天互動 | AI 動態推薦 |
| 根據情境選擇 | AI 動態推薦 |
| 學習調酒知識 | AI 動態推薦 |
| 快速瀏覽推薦 | 計算型推薦（平衡模式）|
| 想嘗試新口味 | 計算型推薦（冒險模式）|
| 穩定探索 | 計算型推薦（平衡模式）|
| 尋求驚喜 | 計算型推薦（冒險模式）|

### 系統整合

兩種模式在系統中的位置：

1. **AI 動態推薦**：
   - 位於對話介面
   - 主要互動方式
   - 需要 LLM API
   - 端點：`POST /api/chat/message`

2. **計算型推薦**：
   - 位於調酒推薦頁面
   - 「為你推薦」區塊
   - 純計算，無需 API
   - 端點：`GET /api/records/recommendations`
   - 參數：
     - `limit`：返回數量（預設 20）
     - `exclude_ids`：已推薦過的調酒 ID（用於分頁）
     - `exploration_mode`：`balanced` 或 `adventurous`

## 技術實現

### AI 動態推薦

**技術棧**：
- LangGraph Agent 狀態管理
- Qdrant 向量搜尋
- MongoDB 資料查詢
- LLM 自然語言處理

**API 端點**：`POST /api/chat/message`

### 計算型推薦

**技術棧**：
- Python 計算邏輯
- MongoDB 聚合查詢（動態隨機抽樣）
- 相似度匹配演算法
- 智能分池和分散化抽取
- 無需 LLM

**API 端點**：`GET /api/records/recommendations`

**查詢參數**：
```
?limit=20&exploration_mode=balanced&exclude_ids=id1,id2,id3
```

## 優勢總結

### AI 動態推薦優勢

- 自然語言理解，無需學習特定格式
- 語義搜尋，理解抽象概念
- 多輪對話，持續優化結果
- 個性化互動，提供情境化建議

### 計算型推薦優勢

- 智能混合四種策略，確保多樣性
- 動態隨機抽樣，避免推薦偏差
- 自動分散化抽取，避免同質化
- 個性化推薦理由，說明推薦邏輯
- 支援冷啟動，新用戶也能獲得好推薦
- 高效能，無需 LLM API 調用

### 綜合優勢

透過結合這兩種模式，本系統能夠：
- 滿足不同場景的推薦需求
- 提供從探索到精準的完整體驗
- 兼顧互動性與效率
- 適應不同用戶的使用習慣
- 在熟悉與新穎之間取得平衡
