# AI 酒保系統

AI 酒保是本系統的核心功能，透過 LangGraph Agent 架構提供智能、互動式的調酒推薦服務。系統結合了大型語言模型（LLM）、專業調酒工具、向量搜尋技術（RAG）和多種酒保性格，提供自然且個性化的互動體驗。

## 系統架構

AI 酒保基於 **LangGraph** 框架構建，是一個具備記憶能力和工具調用能力的對話代理（Agent）。系統會分析用戶的自然語言輸入，理解其需求，並透過呼叫專業工具來提供精準的推薦。

### 核心技術組件

| 技術組件 | 使用技術 | 功能說明 |
|---------|---------|---------|
| **Agent 框架** | LangGraph 1.0.4 | 管理對話流程與狀態機 |
| **LLM 框架** | LangChain 1.1.0 | 提供 LLM 抽象層 |
| **語言模型** | Gemini/Groq/OpenAI | 支援多種 LLM 供應商 |
| **向量資料庫** | Qdrant 1.16.1 | RAG 語義搜尋 |
| **向量編碼** | Sentence-Transformers | 文字向量化（all-MiniLM-L6-v2 模型）|
| **對話儲存** | MongoDB | 保存對話歷史與狀態 |
| **監控追蹤** | LangSmith | 追蹤 Agent 行為和性能 |

## RAG 系統（檢索增強生成）

RAG（Retrieval-Augmented Generation）是 AI 酒保實現語義搜尋的核心技術，讓系統能夠理解抽象的口味描述和情境需求。

### RAG 系統建立流程

#### 1. 資料準備階段

**處理調酒文字資訊**：
- 從 MongoDB 讀取所有調酒資料
- 提取關鍵文字欄位：
  - 調酒名稱（中英文）
  - 口味描述
  - 歷史故事
  - 專業評論
  - 風味檔案描述
  - 標籤資訊

**文字預處理**：
- 清理特殊字元和格式
- 合併相關欄位形成完整描述
- 為每個調酒生成兩種文字描述：
  - **口味描述文本**：強調口感、風味、強度
  - **情境描述文本**：強調適合場合、氛圍、情緒

#### 2. 向量化（Embedding）

**使用模型**：Sentence-Transformers 的 `all-MiniLM-L6-v2` 模型
- 輕量級模型，平衡速度與準確度
- 支援中英文混合文本
- 生成 384 維向量

**向量化過程**：
```
調酒文字描述 → Sentence-Transformers → 384維向量 → 存入 Qdrant
```

**相關腳本**：
- 位置：`backend_flask/scripts/setup_rag.py`
- 功能：
  - 從 MongoDB 讀取調酒
  - 生成向量
  - 寫入 Qdrant
  - 建立索引

#### 3. 向量存儲（Qdrant）

**Collection 結構**：

```
cocktails_taste (口味語義搜尋)
├── vectors: 384維向量
├── payload: {
│   ├── cocktail_id: MongoDB ID
│   ├── name: 調酒名稱
│   ├── name_zh: 中文名稱
│   ├── description: 完整描述
│   ├── tags: 標籤陣列
│   └── metadata: 其他資訊
└── }

cocktails_scenario (情境語義搜尋)
├── vectors: 384維向量
├── payload: {
│   ├── cocktail_id: MongoDB ID
│   ├── name: 調酒名稱
│   ├── scenario_tags: 場合標籤
│   ├── mood_tags: 氛圍標籤
│   └── description: 情境描述
└── }
```

**儲存位置**：
- 本地：`backend_flask/qdrant_storage/`
- 包含索引和資料檔案

#### 4. 索引優化

**建立 HNSW 索引**：
- 快速近似最近鄰搜尋
- 平衡搜尋速度與準確度
- 支援即時更新

### RAG 系統調用流程

#### 使用場景 1：口味語義搜尋

**用戶輸入範例**：
- 「我想要酸酸甜甜的調酒」
- 「推薦清爽的夏日飲品」
- 「想喝濃郁有層次的」

**處理流程**：

1. **接收用戶描述**：AI Agent 識別這是口味相關查詢

2. **調用工具**：`search_by_taste_semantic`

3. **向量化查詢**：
   ```
   用戶描述「酸酸甜甜的調酒」→ Embedding → 384維查詢向量
   ```

4. **相似度搜尋**：
   - 在 Qdrant 的 `cocktails_taste` collection 中搜尋
   - 計算查詢向量與所有調酒向量的餘弦相似度
   - 返回相似度最高的 Top 10-20 個結果

5. **後處理與排序**：
   - 結合專業評分調整排序
   - 過濾不符合基本條件的結果
   - 去除重複推薦

6. **返回結果**：
   - 調酒 ID 列表
   - 相似度分數
   - 匹配原因說明

#### 使用場景 2：情境語義搜尋

**用戶輸入範例**：
- 「適合慶祝升遷的調酒」
- 「想要放鬆心情的飲品」
- 「適合約會的調酒」
- 「派對上大家會喜歡的」

**處理流程**：

1. **接收情境描述**：AI Agent 識別這是情境相關查詢

2. **調用工具**：`search_by_scenario_semantic`

3. **向量化查詢**：
   ```
   用戶描述「適合慶祝的調酒」→ Embedding → 384維查詢向量
   ```

4. **相似度搜尋**：
   - 在 Qdrant 的 `cocktails_scenario` collection 中搜尋
   - 匹配情境、氛圍、社交屬性
   - 考慮調酒的歷史背景和文化意義

5. **智能過濾**：
   - 根據場合過濾（正式/非正式）
   - 根據人數過濾（獨飲/聚會）
   - 根據時段過濾（日間/夜間）

6. **返回結果**：帶有情境匹配說明的調酒列表

### RAG 系統優勢

**相比關鍵字搜尋**：
- ✅ 理解語義：「清爽」能匹配到含薄荷、柑橘的調酒
- ✅ 跨語言：中英文混合查詢無障礙
- ✅ 模糊查詢：不需要精確的專業術語
- ✅ 情境理解：理解「約會」、「慶祝」等抽象概念

**實際效果**：
- 查詢：「夏天海邊的感覺」
  - 結果：Piña Colada、Mojito、Daiquiri（熱帶、清涼風格）

- 查詢：「工作後放鬆」
  - 結果：Old Fashioned、Whiskey Sour（經典、舒適風格）

### RAG 系統維護

**更新向量資料庫**：
```bash
# 當調酒資料更新時，重新建立 RAG 索引
cd backend_flask/scripts
python setup_rag.py
```

**監控與優化**：
- 追蹤搜尋準確度
- 收集用戶反饋
- 定期重新訓練或更換 Embedding 模型

## 酒保性格系統

系統提供 **5 種預設性格** 和 **自訂性格** 功能，每種性格會影響 AI 的回應風格和互動方式。

### 預設性格列表

#### 1. 專業酒保（Professional）
- **ID**：`professional`
- **特色**：專業、精確、注重細節
- **語氣**：正式、專業術語、結構化說明
- **適合**：想要學習調酒知識、追求專業建議的用戶
- **回應範例**：「根據您的口味偏好，我建議嘗試 Negroni。這款經典調酒以琴酒為基底，苦味與甜味達到完美平衡，酒精度數適中（ABV 24%），適合餐前飲用...」

#### 2. 友善酒保（Friendly）
- **ID**：`friendly`
- **特色**：親切、輕鬆、易於交流
- **語氣**：口語化、溫暖、鼓勵性
- **適合**：新手或希望輕鬆探索的用戶
- **回應範例**：「嘿！聽起來你喜歡清爽的口感，那你一定要試試 Mojito，薄荷和萊姆的組合超級消暑，而且做起來也不難喔！」

#### 3. 幽默酒保（Humorous）
- **ID**：`humorous`
- **特色**：風趣、幽默、偶爾開玩笑
- **語氣**：輕鬆活潑、俏皮話、娛樂性
- **適合**：想要輕鬆娛樂體驗的用戶
- **回應範例**：「你說要酒精濃度高的？那我推薦 Long Island Iced Tea，這杯可是出了名的『假裝是茶但其實是烈酒大集合』，小心別喝太快喔！😄」

#### 4. 浪漫酒保（Romantic）
- **ID**：`romantic`
- **特色**：浪漫、優雅、營造氛圍
- **語氣**：詩意、感性、注重情境
- **適合**：約會或特殊場合
- **回應範例**：「在這樣的夜晚，讓我為你推薦 French 75。香檳的氣泡如同星光閃爍，琴酒的清冽配上檸檬的芬芳，這是一杯能讓時光變得柔軟的魔法...」

#### 5. 簡約酒保（Minimalist）
- **ID**：`minimalist`
- **特色**：簡潔、明瞭、直接
- **語氣**：精簡、要點式、高效率
- **適合**：快速查詢、不想囉嗦的用戶
- **回應範例**：「推薦：Gin Tonic。材料：琴酒60ml、奎寧水120ml、萊姆1片。做法：杯中加冰，倒入琴酒和奎寧水，攪拌，裝飾萊姆片。」

### 自訂性格系統

用戶可以創建專屬的酒保性格：

**創建方式**：
- 在個人設定中點擊「創建性格」
- 填寫性格名稱和描述
- 撰寫 System Prompt（定義 AI 的身份和風格）
- 設定可見性（私人/公開）

**System Prompt 範例**：
```
你是一位專注於威士忌的資深酒保，擁有 20 年經驗。
你熱愛分享威士忌的知識，說話時會引用酒廠的歷史故事。
你的語氣專業但不失親和力，喜歡用比喻來描述風味。
```

**儲存位置**：
- MongoDB 的 `personalities` collection
- 包含性格 ID、名稱、描述、提示詞、可見性

**性格分享**：
- 公開性格可以被其他用戶使用
- 形成社群共享的性格資源庫

### 性格實現機制

**System Prompt 注入**：
- 每種性格對應一個 System Prompt 模板
- 預設性格儲存於 `backend_flask/app/prompts/*.md` 檔案
- 在對話開始時注入到 LLM

**Prompt 結構**：
```markdown
# 角色設定
你是一位[性格特色]的酒保...

# 語氣風格
- 使用[語氣描述]的語言
- 避免[不適合的用詞]
- 多用[適合的表達方式]

# 回應原則
1. 提供[專業/友善/幽默]的建議
2. 注重[細節/氛圍/效率]
3. 回應長度[詳細/適中/簡短]

# 範例
用戶：推薦一款調酒
你：[範例回應...]
```

### 性格切換

**切換時機**：
1. **創建對話前**：選擇性格開始新對話
2. **對話中切換**：隨時更換性格（保留對話歷史）
3. **設定預設性格**：在個人設定中設定常用性格

**API 調用**：
```json
POST /api/chat/message
{
  "message": "推薦調酒",
  "conversation_id": "...",
  "personality": "friendly"  // 指定性格 ID
}
```

## AI 工具系統

AI 酒保配備了 7 個專業工具，可以根據對話情境智能選擇使用。

### 工具清單

| 工具名稱 | 功能說明 | 適用情境 |
|---------|---------|---------|
| **search_by_name** | 名稱搜尋 | 用戶詢問特定調酒，如「Mojito 怎麼做」 |
| **search_by_ingredients** | 材料搜尋 | 用戶指定特定材料，如「有琴酒的」、「用蘭姆酒的」 |
| **filter_by_attributes** | 屬性篩選 | 用戶指定具體條件，如「酒精濃度高」、「卡路里低」、「簡單的」 |
| **search_by_taste_semantic** | 語義口味搜尋（RAG） | 用戶描述抽象口味，如「酸酸甜甜」、「清爽」、「濃烈的」 |
| **search_by_scenario_semantic** | 語義情境搜尋（RAG） | 用戶描述場合，如「適合約會」、「派對用」、「慶祝升遷」 |
| **search_by_category** | 分類搜尋 | 用戶查詢特定分類，如「琴酒調酒」、「伏特加調酒」 |
| **get_random_cocktail** | 隨機推薦 | 用戶表示「隨便」、「給我驚喜」、「試試手氣」 |

### 工具詳細說明

#### 1. 名稱搜尋工具

**search_by_name（名稱搜尋）**：
- **功能**：直接搜尋特定調酒的詳細資訊
- **使用場景**：
  - 「Mojito 怎麼做？」
  - 「介紹一下 Old Fashioned」
  - 「Negroni 的配方是什麼？」
- **回傳資訊**：
  - 完整配方和製作步驟
  - 歷史故事和由來
  - 評分和評論
  - 營養和酒精資訊
- **技術實現**：在 MongoDB 中進行名稱模糊匹配，支援大小寫不敏感

#### 2. 材料搜尋工具

**search_by_ingredients（材料搜尋）**：
- **功能**：根據指定的材料或基酒搜尋調酒
- **使用場景**：
  - 「我有琴酒，可以做什麼？」
  - 「用蘭姆酒的調酒」
  - 「含有薄荷的清涼飲品」
  - 「有萊姆汁的調酒」
- **特色**：
  - 支援包含材料邏輯（`any` 或 `all` 模式）
  - `any` 模式：包含任一材料即可
  - `all` 模式：必須包含所有指定材料
  - 按專業評分排序
- **技術實現**：在 MongoDB 的 `ingredients` 欄位中進行精確或模糊匹配

#### 3. 屬性篩選工具

**filter_by_attributes（屬性精確篩選）**：
- **功能**：根據具體的數值或分類屬性篩選調酒
- **支援的篩選條件**：
  - **酒精強度**：`min_strength`、`max_strength`（0-10）
  - **甜度**：`min_sweetness`、`max_sweetness`（0-5）
  - **難度等級**：`difficulty`（easy、medium、hard）
  - **卡路里**：`max_calories`（營養資訊）
  - **分類**：`category`（如 Gin Cocktails）
  - **評分**：`min_rating`（專業評分 0-5）
- **使用場景**：
  - 「找評分 4.5 以上的調酒」
  - 「酒精強度 7 以上的」
  - 「卡路里低於 200 的輕盈選擇」
  - 「簡單容易做的調酒」
- **技術實現**：在 MongoDB 中使用多條件查詢，返回最多 10 個結果

#### 4. 語義搜尋工具（RAG 技術）

詳見上方「RAG 系統」章節。

**search_by_taste_semantic（口味語義搜尋）**：
- **功能**：根據用戶描述的口味進行語義搜尋
- **使用場景**：「我想要酸酸甜甜的調酒」、「推薦清爽的夏日飲品」、「濃烈有層次的」
- **技術原理**：使用 RAG 技術，在 Qdrant 向量資料庫的 `cocktails_taste` collection 中搜尋
- **參數**：
  - `query`：口味描述（自然語言）
  - `limit`：返回結果數量（預設 3）
  - `min_score`：最低相似度閾值（0.65）

**search_by_scenario_semantic（情境語義搜尋）**：
- **功能**：根據用戶描述的場景或心情推薦調酒
- **使用場景**：「適合慶祝升遷的調酒」、「想要放鬆心情的飲品」、「約會時喝的」
- **技術原理**：在 Qdrant 向量資料庫的 `cocktails_scenario` collection 中搜尋，匹配情境、氛圍、社交屬性
- **參數**：
  - `query`：場景描述（自然語言）
  - `limit`：返回結果數量（預設 3）
  - `min_score`：最低相似度閾值（0.65）

#### 5. 分類搜尋工具

**search_by_category（分類搜尋）**：
- **功能**：根據調酒分類或基酒類型搜尋
- **使用場景**：
  - 「琴酒調酒有哪些？」
  - 「給我看伏特加的調酒」
  - 「蘭姆酒的經典款」
  - 「龍舌蘭調酒推薦」
- **特色**：
  - 支援基酒分類（Gin、Vodka、Rum、Tequila 等）
  - 按專業評分排序
  - 返回該分類的熱門調酒
- **技術實現**：在 MongoDB 的 `category` 欄位中進行模糊匹配

#### 6. 隨機推薦工具

**get_random_cocktail（隨機推薦）**：
- **功能**：從資料庫中隨機挑選調酒
- **使用場景**：
  - 「隨便推薦一個」
  - 「給我驚喜」
  - 「試試手氣」
  - 「不知道要喝什麼」
- **特色**：
  - 使用 MongoDB 的 `$sample` 聚合管道
  - 真正的隨機選擇
  - 適合冒險型用戶
- **技術實現**：MongoDB 聚合管道隨機取樣

## 對話記憶機制

AI 酒保具備完整的對話記憶能力，能夠進行多輪連貫對話。

### LangGraph 狀態結構

系統使用 LangGraph 管理對話狀態：

```python
BartenderState {
    messages: List[Message],              # 完整對話歷史
    user_message: str,                     # 當前用戶輸入
    conversation_id: str,                  # 對話 ID
    user_id: str,                          # 用戶 ID
    current_query: dict,                   # 累積的查詢條件
    recommended_cocktails: List[str],      # 已推薦清單
    last_recommendation: dict,             # 最後推薦的調酒
    response: str,                         # AI 回應
    tool_calls: List                       # 工具調用記錄
}
```

### 記憶內容

1. **current_query**：累積的篩選條件
   - 記錄用戶在對話中提到的所有要求
   - 例如：「琴酒」→「琴酒、酸味」→「琴酒、酸味、簡單」

2. **recommended_cocktails**：已推薦清單
   - 避免重複推薦相同調酒
   - 支援「換一個」、「還有其他的嗎」等需求

3. **last_recommendation**：最後推薦
   - 記住上一次推薦的調酒
   - 支援追問詳情：「這個怎麼做？」、「告訴我更多」

4. **conversation_history**：對話歷史
   - 保存完整的對話脈絡
   - 理解指代詞：「它」、「這個」、「那款」

### 記憶應用場景

**場景 1：逐步細化需求**
```
用戶：我想要調酒
AI：好的！你偏好什麼口味呢？
用戶：酸的
AI：了解！酸味調酒有很多種，我推薦...
用戶：要用琴酒的
AI：[結合「酸」+「琴酒」搜尋] 那我建議試試 Gimlet...
用戶：簡單一點的
AI：[結合「酸」+「琴酒」+「簡單」] Gin Sour 非常適合...
```

**場景 2：追問和替換**
```
用戶：推薦清爽的調酒
AI：我建議 Mojito，它有薄荷和萊姆...
用戶：這個材料多嗎？
AI：[記住是 Mojito] Mojito 需要 5 種材料...
用戶：換一個材料少的
AI：[排除 Mojito，保留「清爽」條件] 那試試 Gin Tonic...
```

**場景 3：對比和選擇**
```
用戶：推薦兩款調酒
AI：我推薦 Margarita 和 Daiquiri...
用戶：第一個和第二個有什麼差別？
AI：[記住兩者] Margarita 用龍舌蘭，Daiquiri 用蘭姆酒...
用戶：我選第一個
AI：[記住是 Margarita] 好的！Margarita 的做法是...
```

### 狀態持久化

- **MongoDB 儲存**：完整對話歷史保存在 `conversations` collection
- **跨裝置同步**：用戶在不同裝置登入可繼續對話
- **歷史查詢**：支援查看和搜尋歷史對話

## 調酒卡片提取系統

當 AI 在對話中推薦調酒時，系統會自動提取關鍵資訊並轉換為視覺化卡片。

### 卡片提取流程

1. **AI 回應生成**：Agent 生成包含調酒推薦的回應
2. **智能解析**：系統解析回應文字，識別調酒名稱
3. **資料庫查詢**：從 MongoDB 獲取完整調酒資料
4. **卡片組裝**：結合 AI 推薦理由和資料庫資料
5. **前端渲染**：在聊天介面中顯示互動式卡片

- **調酒名稱**（中英文）

  - 甜度
- **快速操作**：

  - 記錄飲用

## 工作流程總覽

### 完整對話流程

1. **接收用戶訊息** → API 接收 POST 請求
2. **情感分析** → 分析用戶情緒（0-1 分數）
3. **載入對話** → 從 MongoDB 讀取歷史
4. **準備狀態** → 構建 LangGraph 狀態
5. **LLM 推理** → AI 分析用戶意圖
6. **工具選擇** → 自動選擇適合的工具
7. **執行工具** → 查詢資料庫或向量庫
8. **生成回應** → 基於工具結果產生回覆（套用性格風格）
9. **提取卡片** → 結構化調酒資訊
10. **保存對話** → 存入 MongoDB
11. **返回結果** → 回傳給前端

### LangGraph 工作流程圖

```
用戶輸入 → 意圖理解 → 工具選擇 → 工具執行 → 結果整合 → 回應生成
    ↓           ↓          ↓         ↓          ↓          ↓
 自然語言    分析需求   選擇適當   查詢資料   個人化處理  性格化回應
           提取條件    的工具    庫/向量庫   結合記憶   加入卡片
```

### 性能優化

- **向量快取**：常用查詢向量快取
- **資料庫索引**：優化 MongoDB 查詢速度
- **並行處理**：工具調用可並行執行
- **錯誤重試**：LLM 調用失敗自動重試

## 使用建議

### 適合的查詢方式

✅ **自然語言描述**：「我想要一杯適合夏天的清爽調酒」
✅ **情境描述**：「適合慶祝的調酒」
✅ **材料限制**：「有琴酒但沒有奎寧水的」
✅ **多條件組合**：「低卡路里又好喝的調酒」

### 不適合的查詢

❌ 過於模糊：「好喝的」
❌ 超出範圍：「教我做菜」
❌ 資料庫沒有的調酒（會說明並建議替代方案）

### 對於新手用戶
1. 選擇「友善酒保」性格
2. 從場景描述開始：「想要放鬆的調酒」
3. 讓 AI 引導你探索，逐步了解自己的口味

### 對於進階用戶
1. 選擇「專業酒保」或「浪漫酒保」
2. 使用具體的篩選條件和材料名稱
3. 追問製作技巧和變化版本

### 對於冒險型用戶
1. 選擇「幽默酒保」性格
2. 使用「隨機推薦」功能
3. 嘗試跨風格、跨基酒的組合
